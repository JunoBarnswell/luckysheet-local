# 透视、图表与日常处理完整强化交付

本记录跟踪 2026-09-21 确认的完整范围；不把局部实现或构建通过视为阶段完成。

## 2026-09-21 架构决议：移除 Rust

用户已明确要求移除 Rust，继续 React + Java 21 + H2。合并以本分支的规范模型、Java mutation 重放、原生文档和恢复链为准，记录上游 main 的历史但不引入 Rust 切换。这里是显式撤销共享内核方案，不是运行时兼容桥。

- 影响边界：移除上游 Cargo workspace、Rust native/WASM host、kernel-client、artifact manifest、宿主调用服务和 kernel 数据库切换；构建与 CI 只依赖 Node 24/JDK 21/Maven。
- 用户进一步明确“全部按照本分支为基准”：保留本分支文件中心、认证、服务端事务、协作协议、工具栏和行列扩展，不引入 main 的另一套实现。
- 数据边界：保留当前 Java 迁移历史及 V10 文件版本绑定；拒绝未来或不匹配的迁移记录，禁止把 kernel v11 数据库当作旧版库直接打开、repair 或降级。已切换的部署只能恢复切换前备份与对应程序，不能猜测转换。
- 权限与事务不变：Java 校验用户、版本和写入，客户端仅经 OperationEnvelope 提交。验收数据库使用隔离副本，不改写用户原件。
- 门禁：构建前检查无 Rust/WASM 运行入口，补充允许规范迁移与拒绝未来/冲突迁移的后端测试；执行前端静态门禁、Java 测试、打包及真实浏览器。PR 必须无合并冲突，并记录 CI 状态；完整强化范围仍继续跟踪。

本次本地验证：`scripts/build.ps1` 从 `npm ci` 到前端 build/typecheck、Maven clean/package 全部退出 0；前端 boundaries 退出 0。28 个 Java suites、122 tests 无失败、错误或跳过；另有 4 项构建工具测试通过。新增迁移测试使用真实 H2/Flyway，分别验证规范迁移可重开、未来 V999 拒绝且数据保留、V10 checksum 不匹配拒绝且不 repair。核对上游 85 个 Rust 核心路径在当前工作区均不存在；JAR 中 Rust/WASM 宿主产物为 0，包含静态 index 和 Java V10 迁移。

使用该 JAR 重启独立验收服务后，真实内置浏览器重新登录并恢复图表工作簿 r11，图表和单元格正常呈现、原生文件名仍为 XLSX。另存为的拒绝路径保持可见；snapshot、access、summary、native-document-artifact 均返回 200，网络事件未截断，成功路径控制台无 warning/error。服务重启后旧 WebSocket 的一次认证拒绝为预期日志。

## 本轮契约与迁移

- 原生文件 PUT 要求 `X-Workbook-Revision`，在工作簿行锁内比较版本并保存文件；冲突保留原文件。
- Flyway V10 新增可空 `source_revision`。已有文件保留全部字节并标记未绑定，不猜测历史版本。
- checkpoint 返回 `unitId/revision/checksum/created`，不再返回完整工作簿。
- 相同操作 ID 仅允许相同会话、序号、基准版本、mutation 内容及 intent；不同内容返回 `OPERATION_ID_REUSED`。
- 已发送与恢复的操作不可原地 rebase。跨会话草稿不得仅按客户端序号混排。
- 浏览器按 1 秒窗口合并 checkpoint；操作确认即可释放发送队列，原请求保留到 checkpoint 覆盖其提交版本才清理。失败保留日志，显式保存或重连可重试。
- 图表面板使用本地草稿，一次应用一个 `chart.update`；提交携带预期 payload，远端修改导致可见冲突并保留草稿。
- 新工作簿默认保存为 XLSX。SSJSON/SJS 当前只具备单表值投影，包含图表、公式、格式、布局等时返回 `UNSUPPORTED_FEATURE`，不能静默丢弃后显示保存成功。
- 刷新后按服务端 `sourceFileName` 加载已有原生包；删除仅 `document-import` 来源才加载的错误条件。新建后保存的文件也保留原生身份与包内容。
- `WorksheetModel` 的稀疏单元格写入、Java `putCell` 重放和原生导入引用范围共同单调扩展 row/column extent；服务端快照校验拒绝任何落在已声明 extent 外的单元格，避免“单元格存在、图表范围越界”的持久化矛盾。
- OOXML 的 `<dimension>` 只代表已填充网格时，导入会在规范校验前把图表、误差线、相机/截图和 Table 的合法引用范围纳入所属工作表 extent；越出 Excel 边界、目标工作表不存在或反向范围仍明确拒绝。
- DrawingML/VML 容器不再直接判为图片；图片能力依据包关系识别，保留非标准部件路径，避免纯图表文件被图片资源检查拒绝。
- 另存为只等待待提交操作确认，再导出指定格式；不再先改写原文件。失败原因显示在当前对话框内，允许更换格式重试。

## 当前明确未完成

- Rust 架构分歧已按本分支基准处理；kernel v11 的存量数据不支持原位降级，必须恢复切换前完整备份。远端 PR 合并状态与 CI 结果单独记录。
- 完整恢复分支选择界面、跨会话恢复矩阵、权限撤销/浏览器崩溃，以及恢复日志清理的完整浏览器证据。
- 服务端冲突检查与快照重放已按版本区间查询，但历史面板和部分重连调用仍读取全部分页历史。
- 20 类图表及全部子类型尚未同批验收；自动系列编辑、透视字段身份绑定、专项图表语义、共享仪表盘、固定地理资源版本、日常清洗和多文件汇总仍在完整范围内。自定义 GeoJSON 地图成功链路已具备，但还不能替代上述完整地图资源与联动验收。
- 自动系列的工作表范围已经统一用于渲染和 OOXML 导出，并验证普通区域的列、行方向。显式 X/Y/气泡/股价绑定、Table 与报表区域仍需逐类验收。
- 自定义误差线已在图表草稿、命令校验和原生 OOXML 之间绑定正/负数值范围；原生导入遇到无法无损投影的误差线会保留原生图表而非删除误差线。内置浏览器的 Blob 下载事件未返回文件句柄，因此本轮无法将新图表的导出文件作为 ZIP 逐项核对；仍需完成该 XLSX 的导出、重导入与桌面 Excel 验收。
- 自动图表的编辑面板现在可将规范解析后的自动系列实体化为可编辑系列，而不会把二维数据区域错误提交为单个系列；仍需在真实 XLSX corpus 中对导入的自动系列补充浏览器与桌面 Excel 往返证据。
- 大表/公式/透视/图表性能指标尚未测量，不能把移除数组参数展开及误差统计重复计算当作性能通过。
- XLSX/桌面 Excel、五人协作、Windows 安装升级和备份恢复仍待执行。SSJSON 限制不能替代已承诺的 XLSX 原生图表能力。

## 数据与权限边界

Java/H2 继续为持久化权威；所有可见写操作须经过规范 command/mutation 链。共享分析状态需 editor 权限，原始数据不因筛选而改写。快照/协议迁移只在明确边界执行。
